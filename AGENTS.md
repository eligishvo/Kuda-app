# Kuda

Expo / React Native / TypeScript app: pick destinations on a globe that flattens into a map, see flight prices
from TLV, compare itineraries, hand the chosen flights to a trip planner. Android first. Part of the High Command
ecosystem (app id `kuda`, repo `eligishvo/Kuda-app`, Expo project `elidesigninc/kuda`).

Read `docs/HANDOFF.md` first (what's built, what's next). `docs/BRIEF.md` is the spec: don't change it unless the
owner changes a decision, and log any change in HANDOFF.md.

## Stack

- Managed Expo, SDK 58 (React Native 0.88, Expo Router, TypeScript, vitest). It must keep running in **Expo Go**:
  no `android/` or `ios/` folders, and no library that needs a dev build without asking the owner first.
- Expo changes every SDK: check the `expo` major in `package.json` and use the matching docs
  (`https://docs.expo.dev/versions/v<major>.0.0/`), never memory. Add packages with `npx expo install <package>`.
- Map: `@shopify/react-native-skia` drawing, `react-native-gesture-handler` + `react-native-reanimated` gestures,
  `d3-geo` only for "which country contains this point". No tile provider, no map API key.

## Run and test

```bash
npm install
npx expo start        # scan the QR code with Expo Go (phone and computer on the same Wi-Fi)
npm run typecheck
npm test              # vitest: projection maths, drawing, tap hit-testing, selection, report, themes
npm run verify        # the two above plus the Android bundle (slow)
npm run data          # rebuild the bundled map files (only to refresh borders or airports)
```

`KUDA_PREVIEW_DIR=/tmp/out npm test` also writes SVG pictures of the globe, the morph and the flat map, drawn by
the same code as the app: the quickest way to look at a map change without a phone.

## Folder map

| Path | What |
|---|---|
| `src/app/` | Screens (Expo Router): `index.tsx` map + selection sheet, `settings.tsx`, `_layout.tsx` |
| `src/map/projection.ts` | The globe-to-flat projection maths (worklets; unit tested) |
| `src/map/draw.ts` | Turns countries, graticule and airports into paths for one frame (worklets) |
| `src/map/GlobeMap.tsx` | Skia canvas + drag / pinch / tap gestures |

| `src/selection/` | Selected countries / airports (pure functions + a hook that saves them) |
| `src/theme/` | The three themes as token objects, and the theme provider |
| `src/report/` | "Report a problem" → High Command relay |
| `src/storage/` | AsyncStorage wrapper |
| `tests/` | vitest |
| `worker/`, `shared/` | Not there yet: Cloudflare Worker and shared types arrive in phase 2 |

## Conventions

- Colours come only from the theme tokens (`src/theme/themes.ts`); touch targets are at least 44 px.
- Anything that runs during a gesture must be a worklet (`'worklet'` as the first line) and may only call other
  worklets. Keep map maths in `projection.ts` / `draw.ts` so it stays testable in Node.
- Keep features small: one High Command ticket or roadmap item = one piece of work.
- Comments say why, in plain words. The owner reads the code with basic coding knowledge.

## Don't touch

- API keys never go in the app. From phase 2 they live as Cloudflare Worker secrets (`SERPAPI_KEY`,
  `TRAVELPAYOUTS_TOKEN`, `APP_TOKEN`); never commit them or print them.
- `src/map/data/*.json` by hand; `docs/BRIEF.md` without the owner's decision.

## Checks and shipping (owner's standing instruction, same as his other apps)

1. Run `npm run typecheck` and `npm test`. Run `npm run verify` if you changed packages or `app.json`.
2. Update `docs/HANDOFF.md` in the same commit.
3. Commit, merge into `main` and push `main` without asking. The GitHub Action (`.github/workflows/eas.yml`) runs
   the checks and publishes an EAS update. Expo updates are limited: batch changes and push to `main` at the end
   of a phase; use `[skip ci]` for commits that shouldn't publish. Add `[build]` to the commit message when a new
   installable Android app is needed.
4. Don't watch the GitHub run unless the owner asks or a push is refused.

## High Command

Tickets live in `eligishvo/High-Command` as issues labelled `app:kuda`. The "Report a problem" form in Settings
posts to the relay (`app.json` → `expo.extra.highCommand.reportUrl`, `POST /report`). For one ticket the owner
pastes its Brief from High Command: follow it and nothing else.
